## 2. 三条「别被问倒」的口径

1. **口型 = engine.js 移植的能量近似，不是 viseme，常数不自己调**：算法整体沿用本人既有工程 asr 的同款口型引擎（engine.js，约 1300 行、已在运行中系统验证），常数见 plan §5.2——`AnalyserNode`（`fftSize=1024`、`smoothingTimeConstant=0.5`）取时域数据逐点归一 `(b-128)/128` → RMS → `target = clamp((rms - 0.012) * 6.5, 0, 1)`；起音 `level += (target-level)*min(1, dt*18)`、收音释放 `3.6/s`；**双表情** `setValue("aa", level*0.85)` + `setValue("ih", level*0.12)`，整段包 `try/catch`（模型没定义 `ih` 也不能断 rAF）；`speaking = level > 0.06`，静音累计 ≥ `SILENCE_HOLD`（0.45s）才回 idle。技术设计文档 line 147/191 的「TTS 音频能量近似」口径不变，别升级成「口型对得上每个音素」。常数清单与实调占位见 §5（R8 实调记录位）。
2. **两条播放路径、两种接法（别对调）**：WebRTC 远端轨 → `createMediaStreamSource` → analyser，**只取能量、不接 destination**（engine.js `attachStream` 原文就是这么写的，接了会和页面 `<audio>` 双份出声）；`<audio>` 元素路径（REST 降级链 URL 播放）→ `MediaElementAudioSourceNode`，**保持 `source→destination` 是它唯一出声路径**，且只在 `src` 非空且无 `srcObject` 时绑定；对 `srcObject` 绝不绑定（否则「有口型没声音」）。
3. **1.5s 口径：首包 = 第一句完成时刻**：回复侧是**逐句流式 TTS**（plan §4.2b/F1：`app/audio/tts_sentences.py::synthesize_by_sentence` 切句，`reply_stub` 改为逐句合成、逐句入队）——第一句合成完立即写轨，首包只取决于第一句长度、与整段回复长度脱钩，逐句流式听感更「跟手」。当前 LLM 非流式、整段文本到齐才切句，「边生成边合成」留给 迭代 6（plan §4.2b 不排期项，登记在案不许静默消失）。**仍只能证明服务端 ②→⑤**（① 唤醒 / ⑥ 前端播放未测，plan §8 R2）；`provider=mock` 的数字不外推生产 P95。基线表首包口径必须写明「第一句完成时刻」。
