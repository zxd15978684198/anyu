## 零、判定口径与前置

### 0.1 这份清单判什么

语音链路在**非正常麦克风条件**下是否仍然「可解释」：能不能看出连没连上、说完有没有回话、失败时有没有降级提示而不是静默。只判这三件事，不判音质、不判延迟、不判识别准确率。

### 0.2 文案以实现为准

本清单里引用的话术全部抄自代码常量（见每节「预期文案」列的出处）。**实际以当次构建产物在页面上的输出为准**：先按代码实际输出记录，若与清单不一致，登记为缺陷或登记为文案漂移，**不允许为了对上清单去改文案**。

### 0.3 环境与登录（一次性，约 2 分钟）

1. `docker compose ps` 确认 backend / frontend / postgres 等容器 healthy（前端由 nginx 挂 `./frontend/dist`）。
2. 浏览器打开 `https://localhost/`（本地受控证书，首次需确认继续访问）。
3. 登录页点「填入演示账号」，设备编号 `11111111-1111-4111-8111-111111111106`，密钥 `demo-device-secret-0001`，进入长者端主界面。
4. F12 打开 DevTools：保留 **Console**、**Network → WS** 两个面板；Network 面板勾选 Preserve log（拔麦重连时要看历史帧）。

### 0.4 三个固定观察点（每一态都看这三处）

| --- | --- | --- |

## 一、A 态：正常音量（基线）

### A1 判定什么

1. WS 是否连上（`auth_ok` 是否收到）。
2. 按住说话说完一句，是否有识别文本 + 口播回话。
3. 无降级提示（不该出现任何麦克风/服务不可用话术）。

### A2 怎么判

- **看哪里**：状态条显示「连接·正在听」；按住 `data-testid="hold-to-talk"` 按钮时按钮态为 `holding`（`frontend/src/pad/components/HoldToTalk.tsx:172-188`），文案从「按住 说话」变「松开 结束」（`:50-55`）。
- **Console 看什么**：不应出现 `[vad]` 回落告警（`frontend/src/pad/realtime.ts:941` 的「端侧 TEN-VAD 不可用」）；不应出现 `[ice]` 降级（`frontend/src/pad/ice.ts:39`）；不应出现 `[pad]` 唤醒词不可用（`frontend/src/pad/App.tsx:296`）。允许出现 `[login]` 带 trace_id 的日志（`frontend/src/pad/api.ts:65`）。
- **接口看什么**：WS 帧序列 `offer` → `answer` → `asr_start` → `asr_end` → 下行 `asr_final`（上行类型集合见 `app/audio/signaling.py:819`；服务端分派见 `app/audio/webrtc.py:2911` / `:2918`）。若主链路没起，按住说话会走 REST 兜底 `POST /api/audio/utterance`（`frontend/src/pad/rest-client.ts:71`），应返回 200 与 `{text, reply.text, reply.audio_url}`（`:83-106`）。

### A3 15 分钟内可照做的步骤（约 5 分钟）

1. 确认状态条「连接·正在听」，Network → WS 里找到 `/ws/signal`，Frames 里确认已收到 `auth_ok`。（1 分钟）
2. 按住「按住 说话」说一句「今天天气怎么样」，说完松开。（30 秒）
3. 观察：字幕是否出现识别文本；数字人是否开口或出字幕回复；页面有无 notice 提示。（1 分钟）
4. 再重复 2 次（不同长度：短句一句、稍长 3–5 秒），确认不是偶发。（2 分钟）
5. 在 Console 执行 `document.querySelector('[data-testid="hold-to-talk"]')?.getAttribute('data-state')`，按住时应为 `holding`，松开回 `idle`。（30 秒）

### A4 证据留存

- 截图命名：`A-normal-01-statusbar.png`、`A-normal-02-reply.png`（含字幕与回话）。
- Console：右键 Save console log → `A-normal-console.log`；若无异常日志，保留一张空白 Console 截图即可。
- 接口：WS Frames 面板截图 `A-normal-03-ws-frames.png`（含 `auth_ok` / `asr_start` / `asr_end` / `asr_final`）；若走 REST，Network 里复制 `utterance` 请求的 Response JSON 存 `A-normal-04-utterance.json`，并记 HTTP 状态码与 `trace_id`（响应头或 body 里的 trace 字段）。

## 二、B 态：拒绝麦克风权限

### B1 判定什么

1. WS 连接状态：**录像是「连接绿、说不出话」的组合** —— WS 仍可能连着（页面显示「连接·正在听」），但麦克风拿不到。如实记录这个组合，不要因为「连上了」就判通过。
2. 说完有没有回话：**没有**。按下按钮应当直接被拦下，不产生 `asr_start` / 上行音频。
3. 降级提示文案：必须出现麦克风权限被拒的提示，并且**按钮保留可点**（点击引导去打字），不能整屏卡死。

### B2 怎么判

- **看哪里**：按住按钮后页面 notice 出现「麦克风权限被拒绝：请点击地址栏图标允许后重试」（`frontend/src/pad/audio/capture.ts:9-14` `MIC_ERROR_TEXT.not_allowed`）；按钮文案变「暂时听不了，按这里打字」（`frontend/src/pad/components/HoldToTalk.tsx:50-55` `STATE_TEXT.blocked`）；点它应聚焦打字框（`:88-127` 的 `onAskForText`）。
- **Console 看什么**：浏览器自身的 `NotAllowedError` / `Permission denied` 报错（Chrome 会打一条），以及前端 `onSubtitle(..., "notice")` 产生的提示；若主链路建连也失败，`reportDiag` 会带 `webrtc` 通道失败（`frontend/src/pad/realtime.ts:893-901`）。
- **接口看什么**：Network → WS 应**看不到** `offer`/`asr_start`（主链路在 `await mic.start()` 失败后直接 return，不建 PeerConnection、不发 offer）；也不应出现 `POST /api/audio/utterance`。若两者都出现，说明降级路径判错，属缺陷。

### B3 15 分钟内可照做的步骤（约 4 分钟）

1. 浏览器地址栏左侧图标 → 站点设置 → 麦克风改为「阻止」，或直接点「阻止」响应浏览器的授权弹窗。（注意：改为阻止后需要刷新页面才能稳定复现，刷新后需重新登录。）（1 分钟）
2. 刷新 `https://localhost/`，重新「填入演示账号」登录，打开 DevTools 保持 Console 可见。（1 分钟）
3. 按住「按住 说话」说一句，松开。（30 秒）
4. 记录：notice 文案原文、按钮文案、按钮是否仍可点、点击后是否聚焦打字框；同时看状态条是否仍显示「正在听」。（1 分钟）
5. 打开 WS Frames 确认无 `offer` 与 `asr_start`，Network 确认无 `/api/audio/utterance` 请求。（30 秒）

### B4 证据留存

- 截图：`B-denied-01-notice.png`（notice 文案 + 按钮态）、`B-denied-02-blocked-button.png`（blocked 态与可点）。
- Console：`B-denied-console.log`，需能看到权限拒绝报错那一行。
- 接口：`B-denied-03-ws-frames.png`（截图证明无 `offer` / `asr_start`）；Network 面板截图证明无 utterance 请求。

## 三、C 态：拔麦（运行中拔掉 / 禁用麦克风）

### C1 判定什么

1. WS 连接状态：**应当仍是连接着的**（拔的是本地音频设备，不是网络）。页面状态条不会因此变成「已断开」。
2. 说完有没有回话：**没有识别结果**。此时按住说话要么拿不到帧，要么送出静音，松开后应落到「没听清」或服务不可用话术。
3. 降级提示文案：**已知缺口 —— 有一次性提示，但状态不降级**。`frontend/src/pad/realtime.ts:972-976` 对上行音频轨挂了 `ended` 监听，`:1447-1451` 另挂 `devicechange`（`:993` 注册），拔麦瞬间字幕区会出现「麦克风已断开，正在重连…」；重连失败再出一条「麦克风重连失败」（`:1425`），成功则回 `listening`（`:1444`）。缺口在三点：① 状态条不降级，仍显示「连接·正在听」（`frontend/src/pad/App.tsx:905` 只有两档）；② 提示是一次性 notice 字幕，随后续字幕被覆盖，没有持续可见的「麦克风不可用」标识；③ 重连失败后没有重试入口，按钮也不进入 blocked 态。本条按**实测现象如实记录**并登记为风险，不计为「通过」。注意 `frontend/src/pad/audio/capture.ts:47-51` 的 `onDeviceChange` 是未被调用的死导出（realtime 自己实现了一份），别拿它当「拔麦无监听」的证据。

### C2 怎么判

- **看哪里**：拔麦后状态条文案是否变化（预期不变）；按住说话时字幕区是否出现「没听清，请按住按钮再说话」（`frontend/src/pad/components/HoldToTalk.tsx:129-146`，`frames.length === 0` 分支）或「语音服务暂时不可用，请稍后再试」（`:148-169` 失败分支 / `frontend/src/pad/rest-client.ts:11`）。
- **Console 看什么**：`[offline]` 若出现属网络事件（`frontend/src/pad/offline/index.ts:171`），与拔麦无关，不要混判；拔麦本身在 Console 里通常只有浏览器层面的设备变更事件，前端不打印。若走 REST 兜底并失败，会出现 503 相关日志。
- **接口看什么**：WS 仍连（Frames 无 close）；按住说话后可能仍发 `asr_start` / `asr_end` 但无 `asr_final`（静音或无音频帧）；若走 REST，`POST /api/audio/utterance` 可能返回 503 且 `detail` 为「抱歉，语音识别暂时不可用。您可以直接输入文字，或稍后再试。」（`app/api/audio.py:478-484` + `app/core/degrade_speech.py:26-33`），或 413 超长、401 凭证失效（`app/api/audio.py:372-398`）。

### C3 15 分钟内可照做的步骤（约 5 分钟）

1. 先按 A 态说一句成功，确认基线可用、数字人能回话。（1 分钟）
2. 保持页面不刷新、WS 不断，此时在系统里拔掉 USB 麦克风（或在系统声音设置里把该设备「禁用」）。（1 分钟）
3. 观察 5 秒：页面有无提示？状态条有无变化？记下实际现象（预期：字幕出「麦克风已断开，正在重连…」，失败时再来一条「麦克风重连失败…」；状态条不变，仍「正在听」）。（30 秒）
4. 按住「按住 说话」说一句，松开，观察字幕区提示与是否回话。（1 分钟）
5. 看 WS Frames：连接有没有断（预期不断）；有无 `asr_start` / `asr_end` / `asr_final`。看 Network 有无 utterance 请求及其状态码。（1 分钟）
6. 插回麦克风（或重新启用），再按住说话一次，看是否自动恢复（不需要刷新页面）——这是关键补充项，恢复不了说明需要用户重进页面。（30 秒）

- Console：`C-unplug-console.log`（含浏览器设备变更/报错行，若有）。
- 接口：`C-unplug-03-ws-frames.png`（证明 WS 未断 + 帧序列）、`C-unplug-04-utterance.json`（若走 REST，含状态码、`detail` 文案与 trace_id）。
