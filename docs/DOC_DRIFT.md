# 实现与文档漂移台账（轴二：以实现为准）

> 本文件于 2026-11-19 自 `README.md` §12 迁出，**口径与内容一字未改**，只调了标题层级。
> README 保留入口与「三问分流」摘要；台账的新增与状态变更一律在本文维护。
> 另一条轴（早期方案 vs 现行文档）仍在 [`README.md`](../README.md) 的「已知文档冲突」一节。

**为什么有这一节**：后端实现过程中的变更常常没有回写 PRD。AGENTS 前置·铁律 7（2026-11-12 产品负责人裁定）已定「PRD 只划需求范围，正文里的具体数值/字段名/时点/枚举写法/页面写法不作实现与验收依据，与代码不一致时**以实现为准，不记为缺陷、不要求为对齐 PRD 而改代码**」。但「以实现为准」**不等于「文档从此不用管」**——没有常设登记处，漂移就会持续扩大（实例：本文件 §10 曾长期标 PRD v2.7，而 PRD 已到 v3.2；审计 2026-11-12 抓到 v3.0 后一天内又漂到 v3.2，无人处置）。

## 1. 三问分流（每条差异先分类，再决定动作）

| 类型 | 判据 | 动作 | 是否回写 PRD |
| --- | --- | --- | --- |
| **细节漂移** | 差的是数值、字段名、时点、枚举取值写法、页面写法、注释 | **以实现为准，不改代码**；登记本表 | **不必**（PRD 只划范围） |
| **范围漂移** | 差的是能力有无、业务边界、角色权限、状态机、幂等口径 | 以实现为准判验收；**必须回写 PRD**，并按 AGENTS §4-7 **同一次提交**补 `## 修订记录` | **必须** |
| **红线漂移** | 代码与 **AGENTS §7 硬性数值表** 不一致 | **不许自动吸收**：要么改代码对齐 §7，要么先改 §7 写明理由与影响面再改代码 | 改 §7，不改 PRD |

**验收口径固定为**：能力是否存在、链路是否走通、边界是否守住——**不是**参数是否与 PRD 逐字一致。

## 2. 登记规则

- **一条差异只在本表登记一次**；审计 §七、各计划的「偏离」章节改为**引用本表**，不复制正文。
- 每条必须给 `文件:行号` 的实现事实，不接受「代码里改了」这类无坐标描述。
- 状态取值：`待回写` / `已回写` / `豁免` / `待裁决`。**`待回写` 条目数不得跨轮增长**（跨轮增长即视为失控，需当轮处置）。
- 范围漂移回写后，状态改 `已回写` 并填 PRD 修订记录版本号。
