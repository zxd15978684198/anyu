## 0. 本文解决什么

**W2 之前的事实**：前端 `new RTCPeerConnection()` 不传参数，后端从不下发 TURN；浏览器只拿到厂商 STUN，
跨容器 / 跨网段时两侧只播内网地址，ICE 永远走不通，双向通话一律降级为「按住说话」。

**W2 之后**：浏览器在建链前向本端点取一份「本环境可用的 STUN/TURN」，填进
`new RTCPeerConnection({ iceServers })`。同一份代码在本机（`https://localhost`）与服务器
（`https://example.com`）都下发各自能连的地址 —— host 由**请求头**决定，不硬编码。

本文只覆盖 **ICE 配置下发**这一个端点；信令 WS（`/api/audio/ws`）与媒体面（aiortc）仍按各自契约执行，
TURNS/TLS（5349）自 v1.1 起纳入本文：证书仍由 `scripts/gen_dev_cert.py` 生成、compose 挂载进 coturn，
但**下发给浏览器的 `turns:` URL 属于本契约**（见 §2.2、§4）。

## 1. 端点

| 编号 | 方法 | 路径 | 鉴权 | 用途 |
| --- | --- | --- | --- | --- |
| A1 | `GET` | `/api/audio/ice-config` | **设备令牌**（`typ=device`） | 下发浏览器建链所需的 STUN/TURN |

- 鉴权与 pad 登录同一个凭证：`Authorization: Bearer <access_token>`，其中 `access_token` 即
  `POST /api/auth/device/session` 换到的设备会话令牌（`typ=device`，24h）。
- **只允许设备身份**：家属 / 员工令牌持有效凭证但走错入口 → **403**；无凭证 / 凭证失效 → **401**。
  （注意：`app/core/auth.py` 的 `current_device` 依赖在种类不符时给 401；本端点按 W2 裁决**显式判 `kind`**
  并抛 `RoleForbiddenError`，因此**不上**该依赖，见 §5。）
- 无请求体、无查询参数。响应 `Content-Type: application/json`。
- 该端点**不写库、不读库**：不落 `audit_logs`，不触碰任何长者数据（与 `app/api/pad.py` 的 `avatar-config` 同口径）。

### 1.1 请求头

| 头 | 必需 | 用途 |
| --- | --- | --- |
| `Authorization: Bearer <token>` | 是 | 设备令牌 |
| `X-Forwarded-Host` | 否 | **优先**取用：反代后 `Host` 是上游服务名，浏览器认的域名只在这个头里 |
| `Host` | 是（HTTP/1.1 强制） | 兜底取用 |

## 2. 响应（200）

```json
{
  "ice_servers": [
    {
      "urls": [
        "stun:pad.room301.example:3478",
        "turn:pad.room301.example:3478",
        "turns:pad.room301.example:5349?transport=tcp"
      ],
      "username": "anyu",
      "credential": "<TURN_CREDENTIAL 的值>"
    }
  ],
  "ttl_seconds": 3600,
  "generated_at": "2026-11-09T03:00:00Z"
}
```

### 2.1 字段表

| 字段 | 类型 | 可空 | 取值 / 说明 |
| --- | --- | --- | --- |
| `ice_servers` | `array<object>` | 否 | 0 项表示「本环境没有任何 ICE 服务」，见 §4 |
| `ice_servers[].urls` | `array<string>` | 否 | 至少 1 项；元素形如 `stun:<host>:<turn_port>` / `turn:<host>:<turn_port>` / `turns:<host>:<turn_tls_port>?transport=tcp`。**不是** `string`（浏览器两种都收，这里统一给数组，为将来多 host 留位） |
| `ice_servers[].username` | `string` | 条件 | 仅当 TURN 可用时出现；缺省键**不存在**（不是 `null`） |
| `ice_servers[].credential` | `string` | 条件 | 同上；值为 `TURN_CREDENTIAL` 明文 |
| `ttl_seconds` | `integer` | 否 | `TURN_CREDENTIAL_TTL_SECONDS`（默认 3600）；语义见 §5 |
| `generated_at` | `string` | 否 | 服务端生成时刻，UTC、秒级、**以 `Z` 结尾**（`YYYY-MM-DDTHH:MM:SSZ`）。用于排查时钟偏差，前端不解析 |

**形状约束**：STUN 与 TURN 合并进**同一个** `ice_servers` 元素（一个 `urls` 数组），而不是拆成两项 ——
这样 `username`/`credential` 只出现一次，与浏览器 `RTCIceServer` 的语义一一对应（凭据按元素生效）。

### 2.2 `urls` 是怎么拼出来的

```
stun:<host>:<turn_port>
turn:<host>:<turn_port>
turns:<host>:<turn_tls_port>?transport=tcp     # v1.1 起，turn_tls_port > 0 时
```

| 变量 | 来源 | 默认 |
| --- | --- | --- |
| `<host>` | 请求头（§3），**不取配置、不硬编码** | — |
| `<turn_port>` | `TURN_PORT`（Pydantic Settings `turn_port`），与 coturn `--listening-port` 同值，STUN 与 TURN **共用** | `3478` |
| `<turn_tls_port>` | `TURN_TLS_PORT`（`turn_tls_port`），与 coturn `--tls-listening-port` 同值；`<= 0` 表示**不下发** `turns:` | `5349` |

**为什么 `turn:` 与 `turns:` 并列下发**：浏览器对 `turns:` 不做「忽略证书错误」那套交互，
证书不在受信根里时这条会直接失败；同一个 `RTCIceServer` 里的 `turn:`(UDP) 仍会正常拿到 relay，
所以两条并列是「证书受信则升级 TLS、不受信则回落明文」的自动选择，而不是二选一的配置开关。

## 3. `<host>` 的取值规则（W2 的核心）

按下列顺序取**第一个非空**的头：

1. `X-Forwarded-Host`
2. `Host`

然后规范化：

| 步骤 | 规则 | 例 |
| --- | --- | --- |
| 取第一段 | 多级反代按惯例逗号分隔，取最左 | `a.example.com, b.internal` → `a.example.com` |
| 去 scheme | 某些反代会把 `https://` 一并塞进来 | `https://a.example.com/x` → `a.example.com` |
| 去端口 | ICE URL 自带端口；`turn:a.com:8443:3478` 是坏 URI | `a.com:8443` → `a.com` |
| IPv6 | 保留方括号（RFC 7065 形态） | `[::1]:5173` → `[::1]` |

由此得到「同一份代码两处都对」：

| 部署 | 浏览器访问 | 下发 |
| --- | --- | --- |
| 本机 | `https://localhost` | `turn:localhost:3478` |
| 服务器 | `https://sm.example.com` | `turn:sm.example.com:3478` |

**空 host（拿不到任何可用头）**：不拼 `turn::3478` 这种坏地址，直接按「无 STUN/TURN」处理（§4 的全空行），
并打一条带 `trace_id` 的 warning。

## 4. 降级矩阵（**配置不全不是错误**）

配置项（`app/core/config.py`）：`stun_url`、`turn_url`、`turn_username`、`turn_credential`、`turn_tls_port`。

| `stun_url` | TURN 三项 | `turn_tls_port` | `ice_servers` | 说明 |
| --- | --- | --- | --- | --- |
| 有 | 齐 | `>0`（默认 5349） | `[{urls:[stun…, turn…, turns…], username, credential}]` | **默认形态** |
| 有 | 齐 | `<=0` | `[{urls:[stun…, turn…], username, credential}]` | 关掉 TLS 下发（老 coturn 没开 5349） |
| 有 | 任一为空 | 任意 | `[{urls:[stun…]}]` | **TURN 三项任一为空 → 只给 STUN** |
| **空** | 齐 | `>0` | `[{urls:[turn…, turns…], username, credential}]` | 只给 TURN（STUN 独立开关） |
| **空** | 齐 | `<=0` | `[{urls:[turn…], username, credential}]` | 同上，无 TLS |
| **空** | 任一为空 | 任意 | `[]` | **全空 → 空数组** |

铁律：

- **一律 200**。降级不返回 4xx/5xx —— 前端拿到空数组就走无参建连，**不许抛错**（§6）。
- TURN 是否可用只看**三项非空**，不看 URL 是否 loopback：服务端自连会过滤 loopback（`ice_servers()`），
  下发给浏览器时**故意不过滤**（`ice_servers_for_client()`），否则本机 `http://localhost` 联调永远没有 TURN。
- `turns:` 只随 TURN 三项齐备才出现；`turn_tls_port<=0` 是「不下发」而不是错误（保留老 coturn 的退路）。
- **TLS 连不上不是降级**：浏览器对 `turns:` 握手失败只丢这条候选，同一元素里的 `turn:` 照常工作，
  故服务端**不做**「探测 5349 是否可用」这类探测（会引入额外超时与状态）。
- 空串与纯空白视为空（判定用 `strip()`）。

## 5. 错误响应

统一错误体（`ContractAPIRoute`，与身份契约 §7 一致）：

```json
{"detail": "…", "code": "…", "trace_id": "…"}
```

| 场景 | 状态 | `code` |
| --- | --- | --- |
| 不带 `Authorization` 头 | 401 | `TOKEN_INVALID` |
| 令牌过期 / 撤销 / 验签失败 | 401 | `TOKEN_EXPIRED` / `TOKEN_REVOKED` / `TOKEN_INVALID` |
| 家属令牌（`typ=guardian`）、员工令牌（`typ=staff` / `typ=badge`） | 403 | `ROLE_FORBIDDEN` |

> `detail` 面向人读、`code` 面向程序分流、`trace_id` 对齐服务端日志（每行必带）。403 是「凭证体系用错了」，
> 重登换不到设备权限，故**不**用 401 —— 这条与 `current_device` 依赖的默认 401 不同，是本端点的显式选择。

## 6. `ttl_seconds` 的语义（说清边界，避免误读）

- 值 = `turn_credential_ttl_seconds`（`.env` 的 `TURN_CREDENTIAL_TTL_SECONDS`，默认 3600 秒）。
- **当前 `credential` 是长期静态口令**（coturn `--lt-cred-mech` + `--user=<username>:<credential>`），
  服务端**没有**到期轮换机制，`ttl_seconds` 此刻是**提示值**而非强制过期时刻：
  - 前端**不缓存**：每次建链（每个 `auth_ok`）都重新请求一次，不存在「拿旧口令建链」的窗口；
  - 前端**不解析**这个值做续期；它存在的意义是给后续接入 coturn 时限口令
    （`--use-auth-secret` + `TURN REST API` 风格 `username=timestamp:xxx` / `credential=HMAC`）留出接口形状，
    届时语义变为「该口令在 `generated_at + ttl_seconds` 后失效」，前端行为不变。
- 因此**不要把 `ttl_seconds` 当成安全保证**：它现在保证不了任何事，静态口令的残余风险见 §8。

## 8. 残余风险（必须与现状一起读）

| 风险 | 现状 | 处置 |
| --- | --- | --- |
| **长期静态口令** | `TURN_CREDENTIAL` 是常量口令，随每个设备下发；泄露即长期可用（可无限中继流量） | 已在 `docs/SECURITY.md` **§2.5** 登记为残余风险；根治=时限口令（coturn `--use-auth-secret`，见 §6），未排期 |
| 中继端口段暴露 | `49160-49200/udp` 默认发布到宿主机；理论上可被他人扫描复用 | 依赖上面的口令门槛；生产必须改口令，不允许用 `.env.example` 的占位值 |
| `--external-ip` 未指定时 relay 候选不可达 | 本机同网段够用；跨 NAT（服务器 / 局域网外）必须给 coturn `--external-ip=<宿主机 IP>` | `.env.example` 的 `TURN_EXTERNAL_IP` 留空=不传该参数；**需 Lead 用宿主机 LAN/公网 IP 实机验证**（§10 未验项） |
| TURNS 用的是**自签**证书 | 浏览器/系统不信任 `certs/dev.crt` 时 `turns:` 握手失败（无「点继续」交互） | 设计上不致命：同一元素里的 `turn:`(UDP) 照常中继。要真用 TLS 必须把该证书装进受信根（手机：装成 CA 证书；桌面：导入系统根存储）；公网部署换正式 CA 证书 |
