## 2. 鉴权与范围（管理端 M1–M3 共同前提）

> 长者本人端 M4–M6 的前提不同（只认设备主体、`elder_id` 只来自身份上下文），单列在 §6.1。

### 2.1 admin 独占，且先于一切业务判定

- 允许角色只有 `admin`：`ADMIN_ROLES = frozenset({"admin"})`（`app/api/memory.py:111`）。
- 依据是 PRD FR-MEM-02 原话「长者本人可查看/纠正/删除，管理员可协助」（`docs/安语3D数字人_PRD.md:421`）——护工与医生**不在列表里**，理由是记忆含情绪/家庭关系/健康困扰等私密叙述，属护工日常照护之外的最小必要信息（`app/api/memory.py:1-72`）。
- 闸门顺序固定：**角色闸 → 长者范围闸 → 服务层**（`app/api/memory.py:402-403`、`:475-476`、`:549-550`）。

### 2.2 `elder_id` 的来路：只收请求参数，且「声称」不等于「有权」

- M1/M2 只认**查询参数** `elder_id`（`app/api/memory.py:387`、`:439`），M3 只认**路径参数** `{elder_id}`（`app/api/memory.py:535`）；`MemoryWriteIn` **没有** `elder_id` 字段（`app/api/memory.py:169-198`），body 里塞同名值会被忽略而不是 422（**仅读码**；`tests/test_memory_api.py:497-516` 对 M3 断言了 body 值不生效）。
- 参数只是「调用方声称的目标」，拿到后必过 `elder_service.get_elder()`（`app/services/elder_service.py:355-389`）：admin 全量、不存在的长者 404（`:386`）、非 admin 403（`:381`）。
- 这条对应 AGENTS §4 第 9 条（`elder_id` / `thread_id` 只能从服务端注入）：**标识可以来自请求，权限不能来自请求**（`app/api/memory.py:1-72`）。

### 2.3 越权先写审计再抛 403

`_require_admin()` 的两条拒绝分支都**先** `_audit_denied()` 再抛异常（`app/api/memory.py:342-350`）：

- 非 staff（家属/设备）→ `ElderScopeForbiddenError` → 403 `SCOPE_FORBIDDEN`（`app/api/elders.py:86-113`）；
- staff 非 admin → `RoleForbiddenError` → 403 `ROLE_FORBIDDEN`。

审计经 `_write_audit(..., resource_type="memory_chunks", detail={trace_id, reason:"non_admin", role, kind})` 写入独立会话（`app/api/memory.py:318-340`），所以随后的 403 **不会把它回滚掉**（同函数 docstring，`:319`）。
**有测试**：医生调 M3 → 403 `ROLE_FORBIDDEN` 且库里恰一条 `memory.delete` 审计、数据未被删（`tests/test_memory_api.py:476-495`）。

## 3. M1 `GET /api/memory/chunks`

### 3.1 请求

| 参数 | 位置 | 类型/约束 | 默认 | 出处 |
| --- | --- | --- | --- | --- |
| `elder_id` | query | UUID，**必填** | — | `app/api/memory.py:387` |
| `status` | query | **`Literal["active","superseded","deleted"]` 或空**（v1.1 起在 Pydantic 入口收口，非法值直接 422） | `None`（不过滤） | `app/api/memory.py:390-392`；合法值集 `app/services/memory_service.py:114` |
| `limit` | query | 整数，`1 ≤ limit ≤ 200` | `50` | `app/api/memory.py:394`；上限常量 `:118`（理由是单长者上限 `CAPACITY_PER_ELDER=500`，`app/services/memory_service.py:105`） |
| `offset` | query | 整数，`≥ 0` | `0` | `app/api/memory.py:395` |

返回顺序固定为 `created_at DESC, chunk_id DESC`（`app/services/memory_service.py:471-530`）。

### 3.2 响应（200）

`MemoryChunkListOut`（`app/api/memory.py:141-148`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | `MemoryChunkOut[]` | 当前页；单条字段见下表 |
| `total` | int | **当前页条数**，不是过滤后的总数 —— 见 §3.3 |
| `elder_id` | UUID | 回显 |
| `limit` / `offset` | int | 回显 |
| `status` | string \| null | 回显 |

`MemoryChunkOut`（`app/api/memory.py:124-138`）：`chunk_id`、`elder_id`、`content`、`category`、`importance`、`status`、`created_at`、`last_accessed`。
**`embedding` 不返回**（模型里没有该字段，理由见 `:131-135`：上千个浮点数对前端无意义，泄露向量无收益）。

`importance` 是**落库值**，不是调用方提交的基础值：写入时已按 `source` 折算并夹回 `[0,1]`（`app/services/memory_service.py:321`、`:192-208`），所以从 `importance` 无法唯一反推原来的 `source`（表里也没有 `source` 列，只有 `source_thread_id`，`app/models/memory.py:92-99`）。

### 3.3 `total` 的语义（必须按这个读）

`total=len(items)`（`app/api/memory.py:428`）——**当前页条数**，不是 `COUNT(*)`。因此：

- 前端算总页数不能拿 `total / limit`，只能靠「`len(items) == limit` 说明可能还有下一页」；
- 想拿真实总数，需要另开查询（本版没有）；把 `total` 当总数会少算页数。

**仅读码**（无用例断言该语义）。

## 4. M2 `POST /api/memory/chunks`（PRD 未定义的实现补充）

### 4.0 为什么有它（登记，不许当成已定义的 PRD 能力）

- PRD **没有明文定义「记忆写入 API」**：FR-MEM-01 只规定「写入记忆」这个**能力**（`docs/安语3D数字人_PRD.md:420`），FR-MEM-02 只规定长者本人查看/纠正/删除、管理员协助（`:421`）。
- 因此本端点是**实现补充**，登记在 TD v1.12 偏差④（`docs/安语3D数字人_技术设计文档.md:1309`）。登记时写明的动机：原仓库**没有任何 `memory_service.remember` 的生产调用方**，导致「行为推断权重低于明确陈述」这条能力在生产路径上不可达（`source` 参数只在服务层存在）；有了 M2，`inferred` ×0.6 才能取到数。
- **影响面**（登记口径）：
  1. 对外接口**多了一个写端点**（admin only）；OpenAPI 路径数因此增加；
  2. 数据面只往 `memory_chunks` 追加行，**不新增表、不改字段、不需要迁移**（`app/models/memory.py:60-107`）；
  3. 不构成第二套记忆写入形态：M2 与长者端/Agent 的写入链**都只走** `memory_service.remember()`，API 层不出现 `session.add(MemoryChunk)`（`app/api/memory.py:1-72`、`:436-531`）；
  4. 可观测面：日志 `memory_written`（`app/api/memory.py:510-526`）与指标 `memory_write_degraded_total`（`app/services/memory_service.py:297-309`）。
- 本卡写这份契约，就是把「PRD 未定义、但又真实对外开放」这件事从偏差登记升格为**可引用的对外口径**；在此之前**不得**把 M2 当作 PRD 能力引用。

### 4.1 请求

| 参数 | 位置 | 类型/约束 | 默认 | 出处 |
| --- | --- | --- | --- | --- |
| `elder_id` | query | UUID，**必填** | — | `app/api/memory.py:439` |
| `content` | body | 字符串，`1 ≤ len ≤ 200`；**超长拒收，不静默截断** | — | `app/api/memory.py:180-184`；上限常量 `app/services/memory_service.py:95` |
| `category` | body | `private` \| `family` | `private` | `app/api/memory.py:185-187` |
| `importance` | body | 浮点，`0.0 ≤ x ≤ 1.0`（基础值，落库前按 `source` 折算） | `1.0` | `app/api/memory.py:188-193` |
| `source` | body | `explicit` \| `inferred` | `explicit` | `app/api/memory.py:194-197`；`:166` |

默认值取 `explicit`（×1.0）而不是 `inferred`（×0.6）的理由：老客户端不带 `source` 时落库结果必须与加字段前一致；把「没声明来源」默认成「推断」等于悄悄改小既有调用的权重（`app/api/memory.py:169-198`）。

### 4.2 响应（**201 Created**）

`MemoryChunkWriteOut` = `MemoryChunkOut` 全部字段 + 两个可观测标记（`app/api/memory.py:200-214`、`:527-531`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| （同 §3.2 的单条字段） | — | `importance` 为**折算后**的落库值 |
| `embedding_provider` | string | 本次实际使用的 provider 类名（`app/api/memory.py:505`） |
| `semantic_embedding` | bool | `True` 才是真实语义向量；`False` 表示只是联调兜底（`app/api/memory.py:508`） |

### 4.3 `importance` 与来源系数（判定行）

| `source` | 系数 | 落库 `importance`（基础值 1.0 时） |
| --- | --- | --- |
| `explicit`（默认） | 1.0 | 1.00 |
| `inferred` | 0.6 | 0.60 |

- 系数表：`MEMORY_SOURCE_COEFFICIENTS = {"explicit": 1.0, "inferred": 0.6}`（`app/services/memory_service.py:179`）。
- 计算顺序：基础值校验（`0..1`，Decimal 量化到 0.01，`:181-189`）→ 乘系数 → **夹回 `[0,1]`**（`:192-208`）→ 落库（`:321`）。
- `source` 本身**不落库**（`memory_chunks` 无该列，`app/models/memory.py:60-107`），只能从 `importance` 的取值间接推断，且不唯一（例如 `explicit` + 0.6 与 `inferred` + 1.0 结果相同）。
- **有测试**：`tests/test_memory_api_source.py:1-12` 记录了覆盖点——同样基础 `importance=1.0`、`inferred` 从库读回严格小于 `explicit`、比例约 1:0.6、缺省按 `explicit`、非法来源 422 且不写库、body 里的 `elder_id` 被忽略。

### 4.4 `embedding_provider` / `semantic_embedding` 怎么读（**红线**）

- provider 由进程内单例 `_embedding_provider()` 构造，底层是 `build_embedding_provider()`（`app/api/memory.py:258-273`）。四配置（base_url/model/api_key/timeout）不齐时返回 `DeterministicEmbeddingProvider`（SHA-256 派生的**噪声向量**），否则返回 `HttpEmbeddingProvider`（`app/services/embedding.py` 既有实现，本卡未改）。
- `semantic_embedding = not isinstance(provider, DeterministicEmbeddingProvider)`（`app/api/memory.py:508`）；**不按 `provider.available` 判断**——降级实现 `available` 恒为 True，用它判断会把「能算但没语义」误读成「语义可用」（`:506-507`）。
- 降级时：写库照常成功、HTTP 仍 2xx，但 `embedding` 是噪声；**不得**用这批向量产出召回准确率结论（`app/api/memory.py:203-212`，对应 TD 的 S-D7-1 红线）。
- provider 不可用/调用失败时，`remember()` 把 `embedding` 置 `NULL` **照写不误**（`app/services/memory_service.py:297-298`、`:309`），并累加 `memory_write_degraded_total{reason}`；此时**不做 supersede**（只有拿到向量才查冲突，`:311-314`），所以降级期间重复写入会累积多条 active。

### 5.3 删的是什么（判定行）

- 只把该长者 **`status='active'`** 的行改为 `deleted`（`app/services/memory_service.py:683-691`）；`superseded` / 已 `deleted` 的行不动，其它长者的行不动（**有测试**：`tests/test_memory_api.py:419-453`）。
- 同一事务写一条 `audit_logs`：`action="delete_memory"`、`resource_type="memory_chunks"`、`resource_id=elder_id`、`detail={reason, deleted_chunks, soft_delete:true}`、`actor_type` 由 `actor_id` 推（有就是 `staff`，没有就是 `system`）、`actor_id` 缺省落 `elder_id`（`app/services/memory_service.py:694-707`）。**有测试**：`tests/test_memory_api.py:419-453`。
- 服务层只 `flush` 不 `commit`（`:708`），事务由 `get_session` 收口；中途失败整体回滚，不留「删了没记录」或「记录了没删」。
- 软删后 `recall` 的 `status='active'` 过滤立刻生效，下一轮对话不再注入（PRD FR-MEM-05，`docs/安语3D数字人_PRD.md:424`；`app/api/memory.py:533-585`）。

## 6. 长者本人端三端点（M4–M6，FR-MEM-02）

> PRD FR-MEM-02 的原话是「长者本人可查看/纠正/删除，管理员可协助」（`docs/安语3D数字人_PRD.md:421`）。v1.0 只实现了后半句（M1–M3 admin 端），前半句在 v1.1 补齐：**与 admin 三端点并存，不替换**。

### 6.1 鉴权与标识（判定行，比端点本身重要）

- **只认设备主体**：`kind == "device"` 才放行（`app/api/memory.py:352-383` 的 `_require_elder_device()`）。员工 / 家属令牌 → `_audit_denied(reason="not_elder_device")` → 403 `SCOPE_FORBIDDEN`（detail `memory self-service is only reachable by the elder's own device`）。
- **`elder_id` 只从服务端身份上下文取**：`uuid.UUID(identity.elder_id)`（`app/api/memory.py:352-383`）；查询参数与 body 里的 `elder_id` **一律忽略**，不参与寻址。这是 AGENTS §4 第 9 条，也是身份模型本身给的保证——`staff` / `guardian` 身份构造时带 `elder_id` 会直接抛 `IdentityConstructionError`（`app/core/runtime_context.py:78-95`、`:101-110`）。
- **未绑定设备**：`identity.elder_id is None` → `_audit_denied(reason="device_unbound")` → 403 `SCOPE_FORBIDDEN`（detail `elder device is not bound to an elder`）。
- **不复用 `current_device` 依赖**：那条依赖走 `_require_kind`，主体不符抛 `CredentialInvalidError` → 401（`app/core/auth.py:610-617`、`:633`）；本人端要的是 403 + 审计，故自写闸门（`app/api/memory.py:352-383` 的 docstring 记了理由）。
- **跨长者一律 404，不是 403**：`load_chunk()` 的 `WHERE chunk_id=… AND elder_id=…` 把「不存在」与「不属于你」压成同一个结果（`app/services/memory_service.py:733-755`），避免用 UUID 遍历探测他人记忆。
- **有测试**：员工/家属 403 且 `detail["reason"]=="not_elder_device"`、未绑定设备 403（带 `elder_id` 查询参数也不生效，`reason=="device_unbound"`）（`tests/test_memory_me_api.py:490-517`）。

### 6.5 与 admin 端的关系

同一个 `memory_chunks` 表、同一个服务层、同一套审计动作命名（`app/services/memory_service.py` 内两个审计动作常量）。区别只在：admin 端按参数寻址、可批量；本人端按身份寻址、只能操作自己的一条。**不存在第二套写库路径**（AGENTS §4 第 8 条）。

## 6A. 召回注入链路（非 HTTP 端点）

本节不属于六个端点，没有请求/响应；记的是「记忆召回怎么进对话上下文」的内部接缝——它是 `recall` 唯一的对外调用口径，漏了它就会出现「删了 / 别人的记忆还进上下文」。

| 环节 | 口径 | 证据（实读 2026-11-11） |
| --- | --- | --- |
| 身份来源 | 只取服务端本轮判定的 `DialogueIdentity`（`source ∈ device/voice/confirm/generic`）；不读请求体、不接受模型自报 | `app/core/context.py:108`；AGENTS §4.9 |
| 传递 | `DialogueService.respond(identity=…)` → `AgentRunner(text, *, identity=…)` 关键字形参；`runtime_context` 保持 `None`（召回不借用审计/工具语义） | `app/services/dialogue_service.py:154`、`:369`；`app/agents/runtime_factory.py:366` |
| 造 recaller | `build_agent_runner(recall_factory=…)` 每轮按身份现造并覆盖静态 `memory_recall` | `app/agents/runtime_factory.py:333`、`:359-361` |
| 召回 | `build_memory_recaller` → `memory_service.recall(session, elder_id=…, query=…, top_k=5)` → 返回正文列表 → `commit` 刷 `last_accessed` | `app/services/memory_recall.py`；`app/services/memory_service.py:397-469` |
| **generic 恒 None** | 通用模式 / 非法 `elder_id` → **返回 `None`（不构造 recaller、不查库、不注入）**。`None` 表示「本轮没有召回能力」，`[]` 表示「查过没命中」，两者不可混用 | `app/services/memory_recall.py:116-133`；`app/core/context.py:124-133`；AC-28 |
| 失败 | 召回失败只 warning + `memory_recall_degraded_total{reason}`，本轮注入为空，**不得臆造** | `app/agents/companion.py:450-463`；`app/services/memory_service.py:410-426` |
| privacy 收敛 | 该轮整段跳过召回（不查库、不注入） | `app/agents/companion.py:988-991` |

**与 L2 短期记忆的分工（v1.4）**：长期记忆 = 跨会话事实（pgvector，经上表链路按 `elder_id` 强制过滤后注入）；短期记忆 = 最近 5 轮原文（Redis，`thread_id → LIST`，由编排层 `DialogueService` 每轮 load/append）。两者在 L2 轮次里**同时生效**，不是二选一：长期记忆补「这个人是谁、有什么偏好」，短期记忆补「刚才那几句说了什么」。privacy 收敛时**长期记忆整层不注入**（上表最后一行），而**短期记忆照常读写**——双人间里「刚才聊到哪」仍要接得上，只是不许跨会话回忆旁人细节。

## 6B. 长期记忆写入链路（非 HTTP 端点，v1.5）

本节同样不属于六个端点。它记的是「一句话怎么变成一条长期记忆」的两条入口——之前只有话音链路，v1.5 起打字链路也接上了。

| 环节 | 口径 | 证据（实读 2026-11-11） |
| --- | --- | --- |
| 入口一：话音 | `DialogueRuntime._schedule_memory` → `asyncio.create_task`（**不 await**，因提取要调一次 LLM 2–4s，占不进 PRD §5.3 的 1.5s 预算）→ `_run_memory` 带 `wait_for` 且从不抛 | `app/dialogue_runtime.py` 的 `_schedule_memory` / `_run_memory` |
| 入口二：打字 | `run_text_turn(recorder=…, memory_hook=…)` 回完话后调度 `_schedule_memory_writeback`，写法与话音链路同口径（模块级 `_MEMORY_TASKS` 持强引用防 GC、不 await、失败只 warning） | `app/services/text_turn_service.py` 的 `run_text_turn` / `_schedule_memory_writeback` |
| 共同下游 | `MemoryTurnHook.__call__(elder_id, thread_id, user_text, assistant_text)` → `memory_writeback.writeback_memories` → 逐条 `memory_service.remember`（`begin_nested()` SAVEPOINT、内容幂等键 = 归一化正文 SHA-256、同类别 cosine > 0.9 旧行 `superseded`） | `app/services/memory_turn_hook.py`；`app/services/memory_writeback.py`；`app/services/memory_service.py` 的 `remember` |
| 事务边界 | hook **自己开 session 自己 commit**（不并入调用方事务）；提取为空则连 session 都不开，返回 `None` | `app/services/memory_turn_hook.py` |
| 身份 | 只认服务端 `elder_id`；`generic` 或空 `elder_id` 时**不写**（AC-28） | 同 §6A 首行 |
| 失败 | 从不向上抛：`memory_write_degraded_total{reason}`；`embedding` 失败时**照写行**（`embedding=NULL`，降级不丢原文），但该行召回不到 | `app/services/memory_service.py` 的 `remember` |

> 口径提醒：`memory_chunks` 里出现 `embedding IS NULL` 的行是**已知降级形态**，不是脏数据；要判断「写入链活没活」看行数与 `memory_write_degraded_total`，不要只看召回结果。

## 7. 幂等与并发

### 7.1 M1 是幂等的读

只读、不改 `last_accessed`（`app/services/memory_service.py:471-530` 的 docstring 明确「后台翻页不该污染衰减判据」）。重复调用同一参数返回同一页。

### 7.2 M2 不是幂等的

- **没有幂等键**：同一 body 连调两次会生成两条新行（新的 `chunk_id`）。
- 唯一的抑制机制是**相似度取代**：拿到语义向量时，同长者、同类别、`status='active'`、余弦 `> 0.9` 的旧条被置 `superseded`（阈值 `SUPERSEDE_SIMILARITY=0.9`，`app/services/memory_service.py:98`；判定与范围见 `:300-308`、`:345` 起）。
- 因此：
  - 语义 provider 可用时，几乎相同的两条内容最终只有一条 `active`（旧条仍在库，可审计）；
  - **降级（deterministic / embedding 失败）时不做取代**（`:311-314`），重复写入会累积多条 `active`；
  - 相似度取代不是幂等语义：同一请求两次会留下两条历史行，只是其中一条 `superseded`。

### 7.3 M3 效果幂等，但**每次调用都写一条审计**

- 第一次：`deleted_chunks=N`；第二次：`deleted_chunks=0`，仍 200（**有测试**：`tests/test_memory_api.py:455-474`）。
- `audit_logs` 的写入是**无条件**的（`app/services/memory_service.py:694-707` 在 `deleted` 计算之后无条件 `session.add`），所以第二次调用**仍会新增一条 `deleted_chunks=0` 的审计行**——这是重试痕迹，保留（v1.1 起用例 docstring 与代码一致，见 `tests/test_memory_api.py:456`）。

### 7.4 M4–M6 的幂等

- **M4** 只读，天然幂等，且不写 `last_accessed`。
- **M5** 不是幂等：每次成功调用都写一条 `memory.chunk.correct` 审计；内容相同时不会短路（没有「值未变就跳过」的判断）。
- **M6 效果幂等但每次写审计**：重复删同一 `chunk_id` 第二次返回 `deleted=false`、HTTP 仍 200，并**再写一条** `already_deleted=true` 的审计（`app/services/memory_service.py:824-868`）。**有测试**：`tests/test_memory_me_api.py:464-488`。

### 7.5 并发

- M3 用 `UPDATE ... WHERE elder_id=… AND status='active'` + `synchronize_session=False`（`app/services/memory_service.py:683-691`），没有显式行锁/版本号：两个并发 DELETE 都返回 200，但两者的 `deleted_chunks` 之和可能大于实际行数，且各自写一条审计。**仅读码**。
- M2 的 supersede 是「先查再改」（`app/services/memory_service.py:345` 起），并发写入可能都判定为「无冲突」，最终留下两条 `active`。表上**没有内容唯一约束**（`app/models/memory.py:60-107`）。**仅读码**。
- M5/M6 依赖 `load_chunk()` 的「查到即改」，同样是读后写，没有乐观锁；两人同时删同一条只会有一个 `deleted=true`，另一个是 `already_deleted=true`（**仅读码**）。

## 8. 错误码与响应体（自裁行 S-M05）

错误体形状由 `ContractAPIRoute` 统一（`app/api/elders.py:51-56`、`:86-113`）：

```jsonc
{ "detail": "forbidden", "code": "ROLE_FORBIDDEN", "trace_id": "…" }
```

| 码 | 本组端点的触发条件 | `code` |
| --- | --- | --- |
| 400 | 路径参数格式错（M3/M5/M6 的 UUID）或请求体不是合法 JSON | `BAD_REQUEST` |
| 401 | 凭证缺失 / 无效 / 过期 / 已撤销（由 `get_current_principal` 产生） | `TOKEN_INVALID` / `TOKEN_EXPIRED` / `TOKEN_REVOKED`（码表见 `docs/接口契约_身份与权限.md:404`） |
| 403 | 管理端：员工非 admin，或家属 / 设备；本人端：员工 / 家属令牌、未绑定设备 | `ROLE_FORBIDDEN` / `SCOPE_FORBIDDEN` |
| 404 | 长者不存在；**M5/M6：`chunk_id` 不存在、属于别人、或已删除** | `NOT_FOUND` |
| 422 | 查询参数或请求体校验失败（缺 `elder_id`、`limit` 越界、`offset<0`、`status` 不在三值内、`content` 全空白或 >200 字、`reason` >100 字、枚举越界） | `VALIDATION_ERROR` |
| 500 | 服务层未映射异常 | 无统一 `code` 体（FastAPI 默认 500） |
| 503 | 服务层读函数缺件（当前正常不可达，§3.4） | `SERVICE_NOT_READY` |

**409 不由本组端点产生**（没有唯一约束冲突路径），故不列——凑一行会让客户端白写一段处理逻辑。

`trace_id` 必带回，且与响应头 `X-Trace-Id` 一致（**有测试**：`tests/test_memory_api.py:518-526`）。
