# 安语（Anyu）公网部署手册

> 状态：可用（2026-11-13 按本仓现状写）｜ 适用域名：`zhangxianda.online`
> 覆盖层：`docker-compose.prod.yml` ｜ 续期钩子：`scripts/cert_deploy_hook.sh`
> 本文只写「现在这个仓库怎么上公网」，不改任何业务口径。

---

## 0. 一句话结论

**先买一台香港/新加坡的 4C8G 轻量服务器（免备案），用 `pad.zhangxianda.online` 做子域，证书用 DNS-01 签发。**
跑通后再按内存占用决定是否升 8C16G、是否开 funasr/voiceprint 真模型。

| 方案 | 是否需要备案 | 首屏延迟 | 适合 |
| --- | --- | --- | --- |
| 香港/新加坡轻量 4C8G | 不需要 | +30~80ms | **推荐先走这条**：当天就能访问 |
| 中国大陆 4C8G | **需要 ICP 备案**（3~20 天） | 最低 | 演示给国内评委、长期用 |
| 中国大陆 8C16G | 同上 | 最低 | 全量模型 + 多人同时用 |

> 大陆服务器在备案下来之前，域名解析到大陆 IP 的 80/443 会被云厂商直接拦，报错看起来像 nginx 配错——先确认备案再选大陆。

## 1. 机器规格

| 档 | 规格 | 跑什么 | 参考月价 |
| --- | --- | --- | --- |
| 验证 | 4C8G / 80G SSD / 4G swap | 除 funasr、voiceprint 外全部 | ¥150–300 |
| 演示 | 8C16G / 150G SSD | 全量（funasr CPU + voiceprint + laya） | ¥400–900 |
| 低延迟 | GPU 机型 | Laya/ASR 上 GPU | ¥1500+ |

- 系统：**Ubuntu 22.04 LTS**（24.04 也可以，Docker 源要换成 noble）。
- 磁盘：镜像 + 模型 + 数据，100G 起步；`docker system prune` 要写进维护流程。

## 2. 安全组 / 防火墙只开这些口

| 端口 | 协议 | 用途 | 限制 |
| --- | --- | --- | --- |
| 22 | TCP | SSH | **只放自己的出口 IP** |
| 80 | TCP | ACME HTTP-01（可选）+ 301 跳 443 | 全网 |
| 443 | TCP | 页面 / API / WS | 全网 |
| 3478 | TCP+UDP | TURN | 全网 |
| 5349 | TCP+UDP | TURNS（TLS） | 全网 |
| 49160–49200 | UDP | TURN 中继段（与 compose 的 `--min-port/--max-port` 一致） | 全网 |

其余端口（8000/5432/6379/7001/7003/7101/7102）在 compose 里都绑 `127.0.0.1`，**不要**在安全组放行。

## 3. 系统初始化

```bash
# 1) 建普通用户（不要用 root 跑 compose）
adduser deploy && usermod -aG sudo deploy

# 2) 时区 + swap（4C8G 必须加，funasr/laya 峰值会顶到 8G）
timedatectl set-timezone Asia/Shanghai
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 3) Docker + compose 插件
curl -fsSL https://get.docker.com | sh
usermod -aG docker deploy

# 4) 基础防御
apt-get update && apt-get install -y ufw git
ufw allow 22/tcp && ufw allow 80,443/tcp && ufw allow 3478,5349
ufw allow 49160:49200/udp && ufw --force enable
```

## 4. 拉代码与生产 `.env`

```bash
sudo mkdir -p /opt/anyu && sudo chown deploy:deploy /opt/anyu
git clone <你的仓库地址> /opt/anyu
cd /opt/anyu

cp .env.example .env      # 然后用编辑器改，不要直接提交
```

必须改的项（**不要**沿用示例值）：

| 变量 | 生产值 | 说明 |
| --- | --- | --- |
| `APP_ENV` | `production` | 打开密钥强制校验；也决定 `pad/avatar-config` 等演示端点 404 |
| `JWT_SECRET` | `openssl rand -hex 32` | 换掉示例值 |
| `POSTGRES_PASSWORD` | 强口令 | 与 compose 的 `${POSTGRES_PASSWORD}` 一致 |
| `TURN_CREDENTIAL` | 强口令 | 空 = coturn 拒绝启动（刻意） |
| `TURN_EXTERNAL_IP` | 服务器公网 IP | 否则 ICE 只给内网候选，外网连不通 |
| `FRONTEND_ORIGIN` | `https://pad.zhangxianda.online` | CORS 白名单 |
| `RATE_LIMIT_TRUST_FORWARDED_FOR` | 已在 `docker-compose.prod.yml` 设为 1 | 后端在 nginx 后，不设则全站共用一个桶 |
| `RATE_LIMIT_TRUSTED_PROXIES` | `["172.16.0.0/12"]` | 同上，只信 docker 网段 |
| `LLM_API_KEY` / ASR / TTS | 真实 key | 没有就把 provider 留空走 Mock |
| `CELERY_ENABLED` | `true`（要 worker 时） | backend 与 worker/beat 读同一个值 |
| `CERTS_DIR` | `/etc/letsencrypt/live/pad.zhangxianda.online` | 供 `docker-compose.prod.yml` 使用 |

> 红线：公网只能放**模拟数据**。不要导入真实长者/家属信息（AGENTS §4）。

## 6. 证书（DNS-01，不依赖 80 端口）

### 6.1 先签一张

```bash
apt-get install -y certbot
certbot certonly --manual --preferred-challenges dns -d pad.zhangxianda.online
```

按提示在 DNS 控制台加一条 `_acme-challenge.pad` 的 **TXT** 记录，等生效后回车。
成功后证书在 `/etc/letsencrypt/live/pad.zhangxianda.online/`。

> 想自动续期：按 DNS 托管商装插件（Cloudflare 用 `certbot-dns-cloudflare` 官方插件；阿里云/腾讯云有社区插件），
> 之后 `certbot renew --deploy-hook /opt/anyu/scripts/cert_deploy_hook.sh` 即可全自动。

### 6.2 关键一步：把 LE 文件名对成 nginx 期望的名字

`frontend/nginx.https.conf` 里写死的是 `dev.crt` / `dev.key`，我们**不改 nginx 配置**，
而是在挂载目录里放两个软链（certbot 续期后软链仍然有效）：

```bash
sudo mkdir -p /opt/anyu/certs
sudo ln -sf /etc/letsencrypt/live/pad.zhangxianda.online/fullchain.pem /opt/anyu/certs/dev.crt
sudo ln -sf /etc/letsencrypt/live/pad.zhangxianda.online/privkey.pem  /opt/anyu/certs/dev.key
```

`docker-compose.prod.yml` 把 frontend 的 `CERTS_DIR` 指向 LE 目录、coturn 的
`TURN_CERT_FILE/TURN_KEY_FILE` 指向 `fullchain.pem/privkey.pem`——两条路径都对得上。

### 6.3 装续期钩子

```bash
sudo install -m 755 /opt/anyu/scripts/cert_deploy_hook.sh \
  /etc/letsencrypt/renewal-hooks/deploy/reload-anyu.sh
sudo certbot renew --dry-run      # 应看到 deploy hook 执行
```

## 7. 起全栈

```bash
cd /opt/anyu
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build

# 要 Celery（6 条离线批处理）时，优先用脚本：它做 build + --force-recreate + ping 自检，
# 手工 `up -d` 不会重建已存在的 worker 容器，镜像更新后会继续跑旧代码。
#   ./scripts/celery_on.ps1      （停用：./scripts/celery_off.ps1）
# 等价手工命令：
docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  --profile celery up -d --force-recreate backend celery-worker celery-beat
```

首次 `--build` 会构建 backend 镜像，5~10 分钟。

## 8. 验收清单（一条条都能跑）

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://pad.zhangxianda.online/        # 200
curl -sS -o /dev/null -w '%{http_code}\n' http://pad.zhangxianda.online/         # 301
curl -sS https://pad.zhangxianda.online/health                                   # {"status":"ok"} + X-Trace-Id
docker compose ps                                                                # 全部 healthy
docker compose logs --tail=50 backend | grep -i "handed over"                    # CELERY_ENABLED=true 时应有
```

浏览器侧（必须真机验，不能只看 200）：

1. 打开 `https://pad.zhangxianda.online/` → 地址栏锁标正常、无证书告警。
2. 点「允许」麦克风 → **能拿到权限**（失败 = 证书没被信任或不是 HTTPS）。
3. 喊「小伴」→ WS 建连（Network 里 `/ws/signal` 101）。
4. 说一句话 → 有回复、有字幕；看后端日志有 `trace_id`。
5. 用 [Trickle ICE](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/) 输入
   `turn:pad.zhangxianda.online:3478` + 凭据，点 Gather candidates → 必须有 `relay` 候选。
6. `docker compose exec backend curl -s localhost:8000/metrics | head` → 有 Prometheus 文本。

## 9. 备份与维护

```bash
# 每天 03:00 备份（放到 crontab）
docker compose exec -T postgres pg_dump -U anyu anyu | gzip > /opt/backup/sm-$(date +%F).sql.gz

# 磁盘（镜像最容易涨）
docker system prune -af --volumes=false
```

Celery beat 的 schedule 文件在容器 `/tmp`，重启会重建；它是「按时投递」而不是状态机，重建无副作用。

## 10. 常见故障对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 域名打不开、超时 | 大陆服务器未备案，或安全组没开 80/443 | 换香港节点或先备案 |
| 502 | backend 没起 / 健康检查没过 | `docker compose logs backend` 看第一条异常 |
| 页面能开、麦克风没权限 | 证书不被信任或不是 HTTPS | 检查锁标；用 LE 证书而不是自签 |
| 语音连不上（有候选无 relay） | TURN 的 UDP 49160–49200 没开 | 安全组 + ufw 都要放行 |
| `/metrics` 返回 403 | 非回环地址访问（设计如此） | 在服务器上 `docker compose exec backend curl localhost:8000/metrics` |
| 限流把所有人当同一个 IP | 没开 `RATE_LIMIT_TRUST_FORWARDED_FOR` | 用 prod 覆盖层启动 |
| 容器 OOM 被杀 | funasr/laya 峰值超内存 | 加 swap、升 8C16G，或先关掉这两个 profile |

## 附录 A. 新增配置字段说明（`.env.example` 第 12 节）

> 除这三处外，下面字段在公网部署里**不用动**：`RATE_LIMIT_TRUST_FORWARDED_FOR=1`、
> `RATE_LIMIT_TRUSTED_PROXIES=["172.16.0.0/12"]`、`CERTS_DIR=<证书目录>`——
> 前两项生产覆盖层 `docker-compose.prod.yml` 已经写好，`CERTS_DIR` 见本文 §6。

### A.1 请求限流（`app/core/rate_limit.py`）

| 字段 | 管什么 | 默认 | 什么时候改 |
| --- | --- | --- | --- |
| `RATE_LIMIT_ENABLED` | 限流总开关。按「IP + 路由」分别计数，超限返回 429 + `Retry-After` | `true` | 不要关。关掉等于允许暴力刷 `/api/auth/login` |
| `RATE_LIMIT_ENFORCE_IN_DEV` | local/test 环境是否真的拦（默认不拦，否则用例集体 429 互踩） | `false` | 仅本地复现限流时开 |
| `RATE_LIMIT_TRUST_FORWARDED_FOR` | 是否采信 nginx 传来的 `X-Forwarded-For` | `false` | **公网必须开**：不开时后端只看到 nginx 容器 IP，全站共用一个桶 |
| `RATE_LIMIT_TRUSTED_PROXIES` | 只接受这些网段发来的 `X-Forwarded-For`，防伪造 | `[]` | 公网填 docker 网段 `["172.16.0.0/12"]` |

附带行为（无需配置）：`/health` 与 `/metrics` 豁免；被拒日志同一 key 每窗口只记一行。

### A.2 会话体验

| 字段 | 管什么 | 默认 | 调大的后果 |
| --- | --- | --- | --- |
| `IDENTITY_REUSE_WINDOW_SECONDS` | 身份确认后多久不再追问（声纹是软确认，窗口内沿用） | `1800` | 长者少被打断，但「中途换人」更晚被发现 |
| `WEBRTC_ICE_GRACE_SECONDS` | ICE 短暂断开的宽限：多久才判定掉线 | `10` | 不易误挂断；太大则真掉线时页面停在「通话中」 |
| `TTS_BRIDGE_URL` | 容器出网失败时，改问宿主机 `scripts/tts_bridge.py` 合成 | 空 | 仅容器 Edge TTS 出网失败时填 `http://host.docker.internal:7103` |

### A.3 知识与向量

| 字段 | 管什么 | 默认 | 注意 |
| --- | --- | --- | --- |
| `KNOWLEDGE_OUTPUT_GUARD_ENABLED` | 机构知识输出闸门：来源/日期冲突时拦截或改写 | `true` | 关掉退回纯提示词约束，少一道闸 |
| `EMBEDDING_DIMENSION` | 长期记忆向量维度，须与 `EMBEDDING_MODEL` 输出一致（bge-m3 dense=1024） | `1024` | **改它必须迁表并重建向量**，否则入库报维度不匹配、检索失效 |

### A.4 安全与部署

| 字段 | 管什么 | 默认 | 注意 |
| --- | --- | --- | --- |
| `VOICEPRINT_FERNET_KEY` | 声纹 embedding 的加密密钥（Fernet） | 注释掉（用内置 dev key） | 留空时 `APP_ENV=production` 拒绝启动；换钥 = 旧声纹解不开，需重录 |
| `POSTGRES_USER` / `POSTGRES_DB` | 容器建库的库名/用户名，compose 据此拼 `DATABASE_URL` | `anyu` | 只在首次初始化数据卷时生效 |
| `POSTGRES_PASSWORD` | 数据库口令 | `anyu` | 公网必须换；改 `.env` 不改已有库，需同步 `ALTER USER` |
| `CERTS_DIR` | frontend 挂载证书的目录 | `./certs` | 公网指向 LE 目录（§6） |

**两个别乱动**：`EMBEDDING_DIMENSION`（动了要重建向量表）、`VOICEPRINT_FERNET_KEY`（动了要重录声纹）。
